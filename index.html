                Sheet 02 Method
                How I build with agents
                
    
                The same loop for an enterprise platform or a field tool. The model is the cheap part. The context, the evals and the approval step are the product.
                
  
                

  
                
  
  
                

  
                A few things I've learned building agents
                
  
                
    
                One agent, until it isn't enough
                Most problems need one good agent, not five. I split the work only when the pieces can truly run side by side, like the cost-control crew.
                
    
                Let the platform run it
                Managed agent runtimes now handle sandboxes, memory and long sessions. Good. My time goes to what the agent can touch and when a person steps in.
                
    
                Evals come first
                If I can't write the test cases, I don't understand the feature yet. Every miss in production becomes a new case.
                
    
                Context beats prompts
                Agents fail more from what they can't see than from bad wording. Few tools, clean context, and MCP for the plumbing.
                
    
                Trust is earned
                I start with a person approving everything and loosen it as the evals hold up. Anything you can't undo keeps a human.
                
    
                Every task has a price
                Finance taught me to price things, and I still do. Each task gets a cost and latency budget, and the cheaper model goes first.
