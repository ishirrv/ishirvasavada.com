              Sheet 02 Method

              How I build with agents

              Anyone can call an AI model. The product work is deciding what it can see, how we know it's right and when a person signs off.

              Start with one agent

              Most workflows need one capable agent. I add more only when steps can run in parallel, like checking a payment for duplicates and against the budget at the same time. Fewer agents cost less and are easier to fix.

              Use managed agent platforms

              Cloud platforms now handle hosting, memory and long-running tasks for agents. I build on them, so the team's time goes to what users notice: what the agent can access and when it asks for approval.

              Write the tests first

              Before building, we write evals: test cases that define a good answer. Every release has to pass them, and every mistake found later becomes a new test.

              Give agents the right context

              Most AI mistakes come from missing context, not bad prompts. I connect agents to the systems that hold the data, often through MCP, and keep what they see focused.

              Add autonomy gradually

              Agents start with a person approving every action. Approvals loosen as results prove reliable. Anything that can't be undone, like moving money or deleting data, always needs a person.

              Track cost per task

              Each task has a cost and speed target. Routine steps use smaller, cheaper models, and harder calls use the strongest one.
